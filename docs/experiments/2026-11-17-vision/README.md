# Windows 固定机位 ArUco 视觉联调（2026-11-17）

## 已实现与边界

独立入口为 `tools/vision/aruco_live.py`，共用 `aruco_image_test.inspect_frame` 的标记检测和几何校验，复用棋盘透视矫正及 `FULL_CLASSIFIER_ONNX` 整盘分类，不调用 RTMPose。支持离线图片、实时预览、R 重新定位、S 保存、Q 退出，以及有限帧数自动保存和逐格参考布局比对。Windows CPU/GUI 依赖见 `tools/vision/requirements-windows.txt`，启动命令见工具 README。

现场标记按画面方位为左上 3、右上 2、左下 1、右下 0，字典为 DICT_4X4_50。临时映射来自 14:45 照片的手工估计，属于 `test_only=true` 的未确认几何；须显式允许近似映射，不能把重投影一致性解释为棋盘几何真值已确认。正式测量配置与临时配置分开管理。

本次只提交实现和文字记录。个人配置、现场照片、原始样本、诊断拼图和依赖均留在本地忽略目录，不作为仓库公开数据集。

## 人工交换、旋转与局部遮挡实验

两炮交换后的初始样本均为 C。随后在目标格手动旋转，部分朝向下分数下降，后续出现连续 B；重新居中后的 3 帧为 B、B、C。角度和落点均由人工操作，未精确测量，且其他棋子也有移动，因此该序列不能当作严格单变量的朝向实验。

最近 30 组保存样本（16:44:46–17:01:35）已检查原图总览和两炮局部。16:57:09 起的 26 组新增动态挑战样本中：

| 位置 | C | B | x |
| --- | --- | --- | --- |
| (8,5) | 8 | 12 | 6 |
| (8,8) | 16 | 10 | 0 |

26 组中有 22 组至少一枚炮输出 B，全部 26 组在棋盘其他位置还包含 x。这些是刻意采集的挑战样本，不能据此估计自然使用错误率。

直接观察到手指遮住特定局部笔画时，炮/相混淆在两个位置复现；遮住其他部位时也有 C，大面积手掌或手机遮挡则常产生 x。典型目标格错帧为 `20261117-165903-744062`、`20261117-170115-410077`；右侧错帧为 `20261117-165857-989509`、`20261117-170135-775490`；`20261117-170024-593209` 有局部遮挡但仍为 C。部分错误 B 的模型分数约 0.89，因此高分不能单独保证无误。

用户报告强光照射未稳定触发错误。保存的强光实验同时存在手机、手或阴影，不能独立量化光照影响。此前 16:45 等无遮挡样本也存在 B，不能把所有历史错误均归为遮挡。现有证据支持局部可见信息缺失与混淆相关，尚不能证明网络只依赖某一个笔画或排除整盘上下文影响。

离线对照还发现：原分辨率直接矫正可将 16:45:32、16:45:33 两帧的目标格从 B 改为 C，但也让 16:31:12 原本为 C 的一帧变为 B；重新检测标记也未普遍消除错误。因此尚未将修改后的缩放/矫正路径替换进实时入口。

## 下一步（尚未实现）

1. 区分原始分类与可接受棋局：手或遮挡存在时暂停有效棋局更新，清场后重新确认。x 可作为辅助信号，但不能覆盖高分误分类的全部情况。
2. 结合已有棋局和合法走子约束拒绝“炮原地变相”等异常观测；首次摆盘与人工重摆另行确认。单纯多数投票不能解决持续错误。
3. 将无遮挡困难样本、可读局部遮挡和不可读遮挡分别标注。保留真实红相、其他棋种和空位回归，不能把模型预测当真值，或把所有不可读图都强标为炮。
4. 如进行训练，先取得原始训练工程/权重或另建可训练方案，加入遮挡/不确定性目标，并按采集场次分开训练与测试。当前未微调模型，未部署树莓派。
