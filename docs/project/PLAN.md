# 项目方案

## 当前范围

先完成可验证的视觉链路：图片/USB 摄像头 → 四角定位 → 透视矫正 → 10×9 整盘分类 → 逐格结果及置信分数。保留原 RTMPose 路径，并用独立入口探索 ArUco。

## 路径与接口

视觉观测的 Python / JSON 接口、Web 离散坐标及后续控制坐标边界见 [VISION_INTERFACE.md](VISION_INTERFACE.md)。视觉代码先在 `vision` 分支开发、验证并推送。

1. **图像输入**：离线样图或 V4L2 USB 节点。设备号随平台确认，不照搬 Windows 编号。
2. **RTMPose**：复用 `core.chessboard_detector.ChessboardDetector`。`force_pose=True` 强制重做角点，默认路径可缓存。
3. **ArUco 图片工具**：输出 ID、像素角点、缺失项；只有几何配置已确认、标记齐全且误差与入镜检查通过时才报告棋盘标定成功。
4. **矫正接口**：复用 `core.keypoint_helper.extract_chessboard`，传入顺序为 TL/TR/BL/BR。标记自身的四角顺序另为解码方向的 TL/TR/BR/BL，两者不可混用。
5. **分类输出**：10 行×9 列；大写红、小写黑，`.` 为空，`x` 为 other 类。原点为规范化棋盘左上交点，坐标使用 0 基行列。

## 已知问题

现场缺边时原流程仍输出棋局；“输出稳定”不足以作为接受依据。下一阶段需根据角点与可见范围、几何一致性、未知类和分类分数制定拒识门槛，并用完整、裁切、遮挡及移动的独立图集验证。

仓库内只有 TEST_ONLY ArUco 方案，没有正式现场标记尺寸、朝向、偏移或相机畸变参数。合成验证不是现场精度证明。

## 与硬件控制的边界

现有机械臂、固件、AI 模块保留。视觉工具只读图、采集及推理。后续接入控制需另建任务，先定义坐标、状态反馈和可停止的动作步骤。
