# 与队友对接：全盘坐标与串口协议

本文件只适用于xiangqi_strategy。完整CH-RO网页尚无对应的串口输入入口。

## 1. 棋盘数据

每个存活棋子是`{"piece":"R","row":9,"col":0}`。row为0..9整数，col为0..8整数；row0黑方底线，row9红方底线，col0固定左侧。大写红方，小写黑方：K/k将帅、A/a士、B/b象、N/n马、R/r车、C/c炮、P/p兵卒。

每次发送全部存活棋子，未列出的交点为空；不是只发改变的棋子，也不是像素或毫米坐标。空格不发送piece="."。归一化相机旋转和棋子编码后再发送。

完整初局坐标可参考examples/start.json。里面turn用于离线one_step工具；在线observe由对局状态管理轮次。在线observe目前接收pieces，不直接接收fen替代pieces。

## 2. 线路编码

串口默认115200、8N1。线路帧是外层JSON，含payload字符串和crc32，最后加一个LF换行。直接复用protocol.py的pack(message)、unpack(line)、Framer，不要自己猜CRC。examples/wire_example.txt保留了完整线路示例。

Python发送端可用以下方式；示意中的message必须替换成完整请求：

```python
from protocol import pack, unpack, Framer  # 本项目protocol.py中的函数和类。
# serial_port是pyserial的Serial实例；message是内层请求字典。
serial_port.write(pack(message))  # pack(message)返回包含CRC和LF的bytes。
# 接收时用Framer.feed(bytes片段)拆成完整帧，再unpack(frame)读取响应。
```

HTTP POST /api/rpc接收内层JSON，不加CRC外壳。CRC只用于传输检错，不能代替对局校验。

## 3. 实际请求顺序

先在现场确认摆棋，创建真实接口局：

```json
{"id":"new-001","type":"new","mode":"robot","ai_side":"b","board_confirmed":true}
```

从响应state取当前game_id和ply。下面observe示例使用空pieces只是展示字段，**不能直接作为有效棋盘发送**；请填入全部真实存活棋子：

```json
{"id":"obs-001","type":"observe","game_id":"替换成当前game_id","ply":0,"frame_id":1,"stable":true,"confidence":0.99,"pieces":[]}
```

- id每条新请求唯一；重试同一请求保持原id和原内容。
- ply必须是当前已提交半步数；人的走棋接受后会增加。
- frame_id是本局递增的新帧编号，重复或旧帧拒绝。
- stable必须是真，confidence需要实际达到0.95以上，不能为凑接口伪造。
- 人的棋盘变化必须能推断为当前局面的一步合法走棋。

之后控制器主动请求ai，带当前game_id、当前ply和ms搜索时间：

```json
{"id":"ai-001","type":"ai","game_id":"替换成当前game_id","ply":1,"ms":1000}
```

收到PLAN后，按command_id去重执行。控制器先发ack，再真实完成后发done；都带当前game_id、ply及command_id，done带success布尔值。DONE成功后从state.pending取得新verification_token，用动作后新采集的全盘observe携带该token复核；完全相等后才正式提交。

超时当前为ACK约5秒、执行约60秒、DONE后视觉复核约15秒，定义在game.py中；如需调参先与机械臂实际耗时对齐。不得用旧帧、预测结果或serial_peer的假视觉代替真实反馈。

## 4. 常见误解

observe不自动调用AI；网页点击AI也不会向串口主动广播PLAN。如果AI由网页发起，串口控制器要主动请求state，检查pending并对command_id去重。

全盘坐标能描述策略决策的位置，但不自动给出六轴角度或机械臂实际毫米坐标。控制同学还需提供execute_move接口、标定及成功/失败反馈。串口断开后当前线程会停止并报故障，需要处理原因后重启并重新确认棋局。

保留的serial_peer.py只供没有真实运动的协议干跑，不是正式视觉或Arm_Lib执行器。正式联调不要用它伪造成功确认。
